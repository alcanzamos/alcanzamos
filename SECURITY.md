# Seguridad

## Cómo reportar una vulnerabilidad

Repórtala **en privado** con el reporte privado de vulnerabilidades de GitHub de este repositorio: pestaña **Security** → **Report a vulnerability**. No abras un *issue* público ni publiques el detalle antes de que se corrija.

## Qué incluir

- Qué componente afecta (`api/`, `web/`, `movil/`, `infra/`…) y la versión o el commit.
- Pasos para reproducirlo y qué esperabas que pasara frente a lo que pasó.
- El impacto que crees que tiene.
- Si lo tienes, una propuesta de corrección.

## Nunca adjuntes datos personales reales

No incluyas datos de personas reales: nombres, documentos, correos, teléfonos, montos o movimientos de cuentas reales, ni contraseñas, tokens o claves. Usa datos inventados. Si ya expusiste datos reales por error, dilo en el reporte para borrarlos.

## Qué pasa después

El proyecto define un procedimiento ante incidentes de seguridad con cuatro pasos: detectar, contener, avisar y dejar constancia (RT-008). Aún no se promete un plazo de respuesta para los reportes externos; cuando se fije, se escribirá aquí.

## Versiones con soporte

El proyecto está en construcción y todavía no tiene versiones publicadas.
